Phase 1: Lexical Analysis (Scanning)

Live in CodeCraft

Lexical analysis is the initial phase of a compiler that converts the input source text into a sequential stream of discrete tokens. It eliminates whitespace, processes comments, and flags unrecognized characters.

Key Lexical Concepts:
  • Token: An abstract category representing a terminal element (e.g. KEYWORD, IDENTIFIER, INT_LITERAL).
  • Lexeme: The literal character sequence matching a token pattern (e.g. while, counter_val, 3.1415).
  • Pattern: A formal regular expression specifying what forms valid instances of a token.
  • Finite Automaton (DFA/NFA): The mathematical state-machine model used to recognize regular expressions deterministically.
CodeCraft Implementation:
// Input Lexeme Stream:
int count = 10; // line 1

// Generated Token Stream:
1. Token(KEYWORD, 'int', line=1, col=1)
2. Token(IDENTIFIER, 'count', line=1, col=5)
3. Token(OP_ASSIGNMENT, '=', line=1, col=11)
4. Token(INT_LITERAL, 10, line=1, col=13)
5. Token(SEPARATOR, ';', line=1, col=15)

Phase 2: Syntax Analysis (Parsing)

Live in CodeCraft

Syntax analysis validates whether the token stream adheres to the structural rules of the language defined by a Context-Free Grammar (CFG). It constructs an Abstract Syntax Tree (AST) and executes error recovery.

Parsing Methodologies:

Top-Down Parsing (LL): Starts from the start symbol and tries to derive the sentence. CodeCraft implements a Predictive Recursive-Descent Parser with backtracking-free precedence climbing.

Bottom-Up Parsing (LR/LALR): Shifts tokens and reduces matching handles until the start symbol is reached (e.g. Yacc/Bison).

Precedence Climbing: Enforces standard mathematical ordering: Multiplicative (*, /) > Additive (+, -) > Relational (>=) > Equality (==) > Logical AND (&&) > Logical OR (||).

Phase 3: Semantic Analysis & Symbol Tables

Live in CodeCraft

While syntax determines grammar legality, semantic analysis verifies meaning. It answers: Has this variable been declared? Are these operand types compatible? Is a variable being read before being initialized?

Symbol Table Architecture:

A symbol table is a hierarchical dictionary that maps variable and function names to their type, scope depth, declaration line, and memory attributes. When entering a nested block { ... }, a child scope is pushed onto the scope stack and popped on exit.

Semantic Errors Detected by CodeCraft:
Undeclared Identifier: x = 20; without prior declaration.
Duplicate Declaration: Declaring int a; twice in the same scope.
Narrowing Conversion: Assigning float expression to int variable.

Phase 4: Intermediate Code Generation (ICG)

Live in CodeCraft

Intermediate representations decouple language-specific syntax from machine-specific assembly. CodeCraft synthesizes linearized Three-Address Code (TAC) and classic Quadruples.

Three-Address Code (TAC):

Each instruction has at most one operator on the right-hand side and utilizes compiler-generated temporary variables (t0, t1, ...):

// Source Expression: x = a + b * c;
t0 = b * c
t1 = a + t0
x = t1
Quadruple 4-Tuples (Op, Arg1, Arg2, Result):

Phase 5: Machine-Independent Code Optimization

Live in CodeCraft

Optimizations improve performance, reduce instruction counts, and shrink memory footprint without altering program semantics.

Constant Folding

Computes operations on known constants at compile time rather than runtime (e.g. t0 = 10 + 20 becomes t0 = 30).

Algebraic Identities

Simplifies arithmetic rules such as x + 0 => x, x * 1 => x, and x * 0 => 0.

Dead Code Elimination

Discards code branches and temporary variables whose outputs never affect the program outcome.

Common Subexpression

Reuses previous computation results if the operand values have not been modified.

Phase 6: Target Code Generation (Machine Code)

Curriculum Theory Topic

The final compiler phase maps intermediate quadruples into specific target machine assembly (such as x86-64, ARM, or MIPS).

Key Challenges in Target Generation:
  • Register Allocation: Assigning frequently accessed variables to hardware registers (R0, R1, EAX) via Graph Coloring or Linear Scan.
  • Instruction Selection: Choosing the optimal machine opcode (e.g. LEA vs ADD) to minimize CPU cycles.
  • Memory Addressing: Managing the call stack, stack frames, base pointers (EBP), and offset offsets.
Academic Note

In educational Compiler Design coursework, phases 1 through 5 (Lexer, Parser, Semantics, TAC, and Optimization) form the core lab implementation. Target generation is studied as theoretical architecture mapping.
